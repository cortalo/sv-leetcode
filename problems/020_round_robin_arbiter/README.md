# 020 轮询仲裁器 Round-Robin Arbiter

**难度**：Medium ｜ **类型**：组合 + 时序 ｜ **来源**：睿思芯科面试手撕（面试者没写出来）；字节二面「循环优先级怎么实现」；海思、复旦微、芯动；阿里云手撕系列；Apple / Nvidia 面经常见

## 题目
N 个请求者，`req[i]=1` 表示第 i 个请求者申请，输出独热码授权 `gnt`（同一拍组合输出）。
优先级按轮询方式变化：
- 复位后优先级为 `0 > 1 > 2 > ... > N-1`
- 某一拍授权给了第 k 个请求者，则从下一拍开始优先级变为 `k+1 > k+2 > ... > N-1 > 0 > ... > k`（第 k 个变成最低）
- 没有任何请求的拍（`req == 0`），`gnt = 0`，优先级不变
- `gnt` 只能授权给正在请求的请求者

## 接口
```systemverilog
module rr_arb #(parameter int N = 4) (
  input  logic         clk,
  input  logic         rst_n,   // 异步复位，低有效
  input  logic [N-1:0] req,
  output logic [N-1:0] gnt
);
```

## 示例（N=4）
| 拍 | req | 当前最高优先级 | gnt |
|---|---|---|---|
| 0 | 1111 | 0 | 0001 |
| 1 | 1111 | 1 | 0010 |
| 2 | 1001 | 2 | 1000 |
| 3 | 1001 | 0 | 0001 |
| 4 | 0000 | 1 | 0000 |
| 5 | 0110 | 1 | 0010 |

## 测试
N=4、N=7 两个实例，随机请求（包括全 0、全 1、稀疏请求）各 10000 拍，逐拍与参考模型比对。
